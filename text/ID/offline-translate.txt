# PROMPT UNTUK QWEN3.5-MAX — WEB TRANSLATE OFFLINE (VANILLA)

## PERAN
Kamu adalah Senior Front-End Engineer + UI/UX Designer. Tugasmu membangun aplikasi web **translate offline** (tanpa server, tanpa API online, tanpa dependensi framework berat) yang berjalan murni di browser (client-side only). Hasil akhir harus lengkap, bisa langsung dibuka via `file://` atau `http://localhost`, dan berfungsi penuh saat offline.

## TUJUAN
Buat aplikasi web translate offline yang cara kerjanya mirip fitur terjemahan di HP (kamus lokal), tetapi dengan sistem library yang bisa di-load/di-install/update oleh pengguna. Semua data diterjemahkan berasal dari file JSON lokal (dictionary), bukan mesin AI/online.

## TECH STACK (WAJIB)
- HTML5 + CSS3 + JavaScript ES2020+ (Vanilla, tanpa framework, tanpa bundler).
- Modul JS menggunakan `type="module"` (ESM).
- Penyimpanan: **IndexedDB** (wajib) + **OPFS** (opsional, fallback ke IndexedDB jika tidak didukung).
- Ikon: **SVG inline** (dilarang memakai emoji di teks/UI/ikon).
- Tidak boleh memakai CDN eksternal saat runtime (harus benar-benar offline setelah aset lokal diunduh). Boleh menyertakan file SVG/font lokal di folder `assets/`.
- Tidak memakai build tool. Cukup buka `index.html`.

## HALAMAN 1 — `index.html` (Translator Utama)
Elemen wajib:
1. **Header** dengan judul aplikasi + tombol navigasi ke `library.html` (ikon SVG).
2. **Pemilih Bahasa**: dua dropdown.
   - Dropdown A: "Dari" (source).
   - Dropdown B: "Ke" (target).
   - Isi dropdown diambil dari library yang **sudah terpasang** (parse field `translate` menjadi `"X To Y"` → source `X`, target `Y`).
   - Jika pasangan source/target dipilih dan library-nya ada → aktif. Jika tidak ada → tampilkan info "Library belum tersedia, buka halaman Library".
   - Tombol tukar (swap) dengan ikon SVG.
3. **Area Input**: `<textarea>` multi-baris, placeholder "Masukkan teks...".
4. **Area Output**: `<textarea readonly>` atau `<div>` hasil, dengan tombol copy (SVG).
5. **Tombol Aksi**: "Terjemahkan", "Hapus", "Salin".
6. **Status bar kecil** di bawah: menampilkan jumlah karakter, status "Offline Ready", dan indikator library aktif.
7. Semua aksi tanpa reload halaman. Responsif (mobile-first) dan aksesibel (label, aria, focus ring).

Logika terjemahan wajib:
- Lookup **frasa terpanjang dulu** (multi-kata) → baru per kata.
- Case-insensitive untuk lookup, tetapi pertahankan kapitalisasi output.
- Pertahankan tanda baca di akhir kalimat.
- Jika kata tidak ditemukan → biarkan kata asli (tidak error).
- Terjemahan berjalan tanpa jaringan.

## HALAMAN 2 — `library.html` (Manajemen Library)
Elemen wajib:
1. **Header** dengan tombol kembali ke `index.html` (SVG).
2. **Tab / Section**:
   - **Tersedia Online** (dari URL manifest GitHub Releases).
   - **Terpasang** (dari IndexedDB/OPFS).
3. **Section "Tersedia Online"**:
   - Ambil daftar manifest JSON dari `https://github.com/azrielspace852-wq/releases` (boleh di-config di `config.js`, contoh default: manifest URL dapat diarahkan ke raw JSON rilis).
   - Render setiap item sebagai card: nama translate (misal "Indonesia To English"), versi, tombol aksi.
   - Tombol berubah otomatis:
     - Jika belum terpasang → **"Install"**.
     - Jika sudah terpasang dan versi sama → **"Terpasang"** (disabled).
     - Jika sudah terpasang dan versi berbeda → **"Update"** (highlight).
   - Klik Install/Update → unduh file JSON library → simpan ke storage → refresh state.
4. **Section "Terpasang"**:
   - List library terpasang: nama, versi, ukuran, jumlah entri, tombol "Hapus".
   - Tombol "Hapus" minta konfirmasi modal dulu.
5. **Load dari File Lokal (Internal Storage)**:
   - Tombol "Impor dari File" → `<input type="file" accept=".json,application/json">`.
   - Validasi isi file: harus objek `{ "input": "output", ... }` (string ke string). Tolak jika tidak sesuai.
   - Simpan ke IndexedDB/OPFS.
   - Minta nama library + source/target jika metadata tidak ada di file. Simpan metadata.
6. **Indikator Storage**:
   - Tampilkan status "OPFS Aktif" atau "Fallback: IndexedDB".
   - Tampilkan estimasi ukuran terpakai (`navigator.storage.estimate()`).

## FORMAT DATA (WAJIB DIIKUTI)

### 1. File Library (kamus) — format internal:
```json
{"input":"...","output":"..."}
```

Contoh:

```json
{
  "kucing": "cat",
  "rumah": "house",
  "selamat pagi": "good morning"
}
```

· Semua key & value bertipe string.
· Boleh berisi frasa multi-kata.

2. Manifest Link Library (dipakai untuk halaman "Tersedia Online"):

```json
{
  "translate": "Indonesia To English",
  "version": "1.0.0",
  "link": ["https://.../id-en-1.0.0.json"]
}
```

Ketentuan:

· translate: format wajib "<Source> To <Target>" (dipisah  To ).
· version: string semver (x.y.z).
· link: array URL ke file library (boleh >1, misalnya dipecah per kategori; aplikasi harus merge seluruh link menjadi satu dictionary). Jika array >1, ukuran total ditampilkan di UI.
· Manifest bisa berupa array berisi banyak objek seperti di atas (list library), atau satu objek tunggal. Tangani keduanya.

ALUR KERJA (WAJIB DIIMPLEMENTASI)

A. Load dari Manifest Online

1. Fetch manifest dari config.js (MANIFEST_URL, default menuju https://github.com/azrielspace852-wq/releases).
2. Parse jadi array library.
3. Bandingkan dengan library terpasang (match berdasarkan translate):
   · Tidak ada → status Install.
   · Ada & version sama → Terpasang.
   · Ada & version beda → Update.
4. Klik Install/Update → fetch semua URL di link → merge jadi satu objek dictionary → simpan ke storage beserta metadata { translate, version, installedAt, entryCount, sizeBytes }.

B. Load dari File Lokal

1. Pilih file .json via <input type="file">.
2. Baca file, cek validasi (objek, value string).
3. Minta pengguna mengisi translate (dropdown source/target) + version (default "1.0.0").
4. Simpan ke storage + metadata.

C. Update

· Jika user telah install "Indonesia To English" v1.0.0, dan manifest menampilkan v1.1.0 → tombol berubah jadi Update.
· Klik Update → unduh versi baru → timpa versi lama → tampilkan toast "Berhasil diperbarui ke v1.1.0".
· Rollback tidak perlu, tapi konfirmasi sebelum overwrite.

D. Translate (di halaman index)

1. Ambil library aktif dari storage (berdasarkan pasangan source/target).
2. Normalisasi input (lowercase untuk lookup, simpan original untuk output).
3. Tokenisasi: coba frasa (2-4 kata) dulu, lalu 1 kata.
4. Hasil dirakit, kapitalisasi disesuaikan, tanda baca dipertahankan.
5. Tampilkan hasil di area output.

PENYIMPANAN (WAJIB)

IndexedDB

· Nama DB: offline-translator-db (di config.js).
· Object store:
  · libraries — key: translate (misal "Indonesia To English"), value: { translate, version, source, target, installedAt, entryCount, sizeBytes, data } (data berupa objek dictionary).
  · meta — key-value kecil (misal lastManifestFetch, preferredPair).
· Gunakan wrapper storage.js dengan API async: saveLibrary, getLibrary, getAllLibraries, deleteLibrary, getMeta, setMeta.

OPFS (dengan fallback)

· Deteksi dukungan: 'storage' in navigator && 'getDirectory' in navigator.storage.
· Jika didukung: simpan file library sebagai file JSON di OPFS (/libraries/<slug>.json), dan simpan metadata kecil di IndexedDB.
· Jika tidak didukung: semua data disimpan di IndexedDB (termasuk data di object libraries).
· Aplikasi wajib tetap berfungsi penuh saat OPFS tidak tersedia.
· Tampilkan status sumber storage di UI (OPFS / IndexedDB).

ERROR HANDLING & VALIDASI (WAJIB)

· Fetch manifest gagal (offline / CORS) → tampilkan pesan ramah: "Gagal memuat daftar library. Periksa koneksi atau URL manifest." + tombol "Coba lagi".
· File library tidak valid (bukan objek / value bukan string) → tolak + pesan jelas.
· Library dengan translate duplikat saat install lokal → tanya: timpa atau batalkan.
· File kosong / 0 entri → tolak.
· Saat OPFS gagal inisialisasi → otomatis fallback IndexedDB (log info, bukan error).
· Saat user menekan Translate tapi library belum terpasang → arahkan ke halaman library.
· Semua try/catch wajib menangani error storage & fetch.
