BAGIAN 6: KATALOG MIGRASI MODERNISASI ANDROID
Migrasi M1: Java ke Kotlin.
Ciri lama: file .java dengan sintaks Java.
Ciri baru: file .kt dengan sintaks Kotlin.
Strategi: migrasi per file, uji setiap migrasi.
Adaptor: kelas Java tetap dipanggil dari Kotlin.
Risiko: perubahan perilaku nullability.
Pengujian: tes unit sebelum dan sesudah.
Dokumentasi: catatan migrasi di docs/migrasi/java-ke-kotlin.md.

Migrasi M2: Support Library ke AndroidX.
Ciri lama: import android.support.*.
Ciri baru: import androidx.*.
Strategi: refaktor otomatis dengan Android Studio.
Adaptor: Jetifier untuk dependensi lama.
Risiko: konflik resource.
Pengujian: build dan tes lengkap.

Migrasi M3: XML layout ke Jetpack Compose.
Ciri lama: file layout XML.
Ciri baru: fungsi @Composable.
Strategi: migrasi per layar, pertahankan View system selama transisi.
Adaptor: ComposeView di dalam XML, atau XML di dalam Compose.
Risiko: perbedaan perilaku UI.
Pengujian: screenshot test sebelum dan sesudah.

Migrasi M4: MVP ke MVVM atau MVI.
Ciri lama: Presenter dengan View interface.
Ciri baru: ViewModel dengan StateFlow.
Strategi: migrasi per layar, pertahankan Presenter lama selama transisi.
Adaptor: Presenter membungkus ViewModel sementara.
Risiko: perubahan alur state.
Pengujian: tes Presenter lama, tes ViewModel baru.

Migrasi M5: KAPT ke KSP.
Ciri lama: kapt untuk Room, Hilt, Moshi.
Ciri baru: ksp untuk pustaka yang mendukung.
Strategi: migrasi per modul, uji setiap modul.
Adaptor: beberapa pustaka masih membutuhkan KAPT.
Risiko: perbedaan hasil generate.
Pengujian: build dan tes lengkap.

Migrasi M6: Groovy ke Kotlin DSL.
Ciri lama: build.gradle dengan sintaks Groovy.
Ciri baru: build.gradle.kts dengan sintaks Kotlin.
Strategi: migrasi per file, uji setiap migrasi.
Adaptor: konfigurasi campuran selama transisi.
Risiko: perbedaan tipe dan resolusi.
Pengujian: build lengkap.

Migrasi M7: Dagger ke Hilt.
Ciri lama: komponen Dagger manual.
Ciri baru: @HiltAndroidApp dan @AndroidEntryPoint.
Strategi: migrasi per modul, mulai dari modul aplikasi.
Adaptor: modul Dagger tetap dipakai oleh Hilt.
Risiko: perbedaan scope dan lifecycle.
Pengujian: tes unit dan tes instrumen.

Migrasi M8: LiveData ke StateFlow.
Ciri lama: LiveData dan Observer.
Ciri baru: StateFlow dan collect.
Strategi: migrasi per ViewModel, mulai dari ViewModel sederhana.
Adaptor: asLiveData dan asStateFlow untuk interoperabilitas.
Risiko: perbedaan lifecycle.
Pengujian: tes ViewModel.

Migrasi M9: SharedPreferences ke DataStore.
Ciri lama: SharedPreferences.
Ciri baru: Preferences DataStore atau Proto DataStore.
Strategi: migrasi per preferensi, mulai dari preferensi sederhana.
Adaptor: migrasi otomatis dari SharedPreferences ke DataStore.
Risiko: kehilangan data jika migrasi gagal.
Pengujian: tes migrasi data.

Migrasi M10: Gson ke Moshi atau kotlinx.serialization.
Ciri lama: Gson dengan refleksi.
Ciri baru: Moshi codegen atau kotlinx.serialization.
Strategi: migrasi per model, mulai dari model sederhana.
Adaptor: konverter Gson di Retrofit selama transisi.
Risiko: perbedaan perilaku nullability.
Pengujian: tes serialisasi dan deserialisasi.

Migrasi M11: Picasso atau Glide ke Coil.
Ciri lama: Picasso atau Glide.
Ciri baru: Coil dengan Compose.
Strategi: migrasi per layar, mulai dari layar utama.
Adaptor: wrapper pemuatan gambar selama transisi.
Risiko: perbedaan cache dan transformasi.
Pengujian: tes UI dan screenshot.

Migrasi M12: Satu modul ke multi-modul.
Ciri lama: satu modul app/ dengan banyak paket.
Ciri baru: banyak modul feature/ dan core/.
Strategi: migrasi per domain, mulai dari domain yang paling independen.
Adaptor: modul app/ bergantung pada modul baru.
Risiko: dependensi melingkar.
Pengujian: build dan tes per modul.
