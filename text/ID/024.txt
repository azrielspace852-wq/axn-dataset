APA ITU GIT: DEFINISI DAN KONSEP DASAR
GIT adalah sistem kontrol versi terdistribusi yang dirancang untuk mengelola perubahan kode, dokumen, dan file proyek.
Fungsi inti GIT adalah menyimpan riwayat perubahan sehingga proyek dapat dilacak, dibandingkan, dan dipulihkan.
Sebagai sistem terdistribusi, setiap pengguna dapat memiliki salinan repositori lengkap beserta seluruh sejarah proyek.
Desain GIT lebih menekankan pada snapshot daripada penyimpanan perbedaan file secara incremental.
Snapshot berarti GIT merekam keadaan seluruh file pada waktu tertentu, bukan hanya selisihnya.
Pendekatan ini menjadikan operasi pembandingan dan pemulihan menjadi cepat dan efisien.
GIT tidak bergantung pada server pusat untuk menjalankan sebagian besar perintah.
Kecepatan menjadi salah satu keunggulan GIT dalam proyek berskala besar.
GIT mampu menangani repositori dengan ratusan ribu file tanpa degradasi kinerja parah.
Integritas data dijaga dengan sistem hash kriptografis yang melekat pada setiap objek.
Hash kriptografis memastikan konten objek tidak berubah tanpa terdeteksi.
Struktur data GIT dibangun dari objek blob, tree, commit, dan tag.
Repositori GIT terdiri dari direktori kerja, area staging, dan basis objek.
Area staging adalah indeks tempat perubahan dikumpulkan sebelum dijadikan commit.
Repositori GIT dapat bersifat lengkap atau bare untuk digunakan sebagai server kolaborasi.
Repositori lengkap berisi direktori kerja yang dapat diedit pengguna.
Repositori bare hanya menyimpan basis objek dan metadata tanpa direktori kerja.
GIT mendukung banyak branch dalam satu repositori.
Branch di GIT hanyalah pointer ringan menuju suatu commit.
Pointer ringan membuat pembuatan dan penghapusan branch berlangsung sangat cepat.
Tag di GIT digunakan untuk menandai titik tertentu seperti rilis versi.
Tag dapat berupa objek sederhana atau objek bertanda tangan.
Merge dan rebase adalah dua cara utama untuk menggabungkan perubahan branch.
Merge mempertahankan riwayat asli kedua cabang.
Rebase menulis ulang riwayat agar tampak linier.
GIT mendukung konflik dan memiliki prosedur penyelesaian yang eksplisit.
Konflik terjadi ketika perubahan pada bagian yang sama tidak dapat digabungkan otomatis.
Pengguna harus mengedit konflik, memarkir penyelesaian, lalu melanjutkan operasi.
GIT menyediakan perintah diff untuk melihat perubahan sebelum commit.
GIT menyediakan perintah log untuk membaca riwayat proyek.
GIT menyediakan perintah show untuk menampilkan detail objek atau commit.
GIT menyimpan metadata commit seperti penulis, waktu, pesan, dan induk.
GIT dapat menampilkan graph riwayat untuk memahami percabangan.
GIT mendukung operasi offline untuk sebagian besar fungsi lokal.
Pengguna dapat melakukan commit tanpa koneksi ke server pusat.
Sinkronisasi dengan repositori lain dilakukan melalui fetch dan push.
GIT mendukung protokol SSH dan HTTPS untuk pertukaran data.
GIT juga memiliki mekanisme kerja sama berbasis patch email.
Mekanisme patch email sangat relevan pada proyek kernel Linux.
GIT memiliki banyak subperintah yang dapat dipanggil sebagai git-subcommand.
Antarmuka baris perintah GIT bersifat seragam di berbagai platform.
GIT dapat dijalankan bersama antarmuka grafis untuk pengguna yang lebih visual.
GIT dapat diintegrasikan ke editor kode, IDE, dan pipeline otomatis.
GIT bukan bahasa pemrograman, melainkan alat manajemen perubahan.

Perbedaan antara GIT lokal dan GIT pusat perlu dipahami agar tidak keliru.

Hash kriptografis menghasilkan alamat tetap berdasarkan isi objek.
OBJEK BLOB menyimpan isi file tanpa metadata nama dan tanggal.
OBJEK TREE menyimpan hubungan nama file ke blob atau tree lain.
OBJEK COMMIT menyimpan pointer ke tree, induk, penulis, dan pesan.
OBJEK TAG dapat menandai commit dan menyimpan metadata tambahan.
Direktori kerja adalah tempat pengguna mengedit file secara aktual.
