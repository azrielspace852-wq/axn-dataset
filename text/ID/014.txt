1. PENGERTIAN UMUM
JSON adalah singkatan dari JavaScript Object Notation, yaitu format teks terbuka (open standard) yang digunakan untuk menyimpan dan mentransmisikan objek data yang terdiri dari pasangan nama-nilai (name-value pairs) dan array. JSON adalah format pertukaran data yang ringan, berbasis teks, dan independen terhadap bahasa pemrograman tertentu.

Meskipun namanya mengandung "JavaScript" dan sintaksnya diturunkan dari notasi objek JavaScript, JSON bukanlah bahasa pemrograman. JSON adalah bahasa penanda (markup) untuk data. Hampir semua bahasa pemrograman modern—termasuk Python, Java, C#, PHP, dan Go—memiliki pustaka bawaan untuk menghasilkan (serialize) dan membaca (parse) data JSON. JSON menggunakan konvensi yang familiar bagi programmer bahasa C-family, sehingga mudah dibaca dan ditulis oleh manusia, sekaligus efisien untuk diurai oleh mesin.

2. SEJARAH, PENCIPTA, DAN ASAL USUL
JSON diciptakan oleh Douglas Crockford, seorang programmer dan pengembang perangkat lunak berkebangsaan Amerika Serikat.

Asal Negara: Amerika Serikat.
Tahun Diciptakan: 2001 (format pertama kali dispesifikasikan dan dipopulerkan).

Crockford menyadari bahwa sintaks literal objek dalam JavaScript (yaitu cara menulis objek langsung di dalam kode JavaScript) sangat cocok untuk dijadikan format pertukaran data. Pada Maret 2001, di sebuah perusahaan bernama State Software yang ia dirikan bersama rekannya, gagasan ini mulai dibahas. Crockford dan Chip Morningstar kemudian mengirim pesan JSON pertama pada April 2001.

Ada cerita menarik di balik penamaan. Awalnya, mereka mempertimbangkan nama "JSML" (JavaScript Markup Language), tetapi karena singkatan itu sudah dipakai, mereka memilih "JavaScript Object Notation" atau JSON. Situs web json.org diluncurkan pada tahun 2001 dan menjadi tempat publikasi spesifikasi awal JSON.

3. SEJARAH VERSI DAN STANDARDISASI
Meskipun JSON tidak memiliki "versi" dalam arti rilis perangkat lunak seperti bahasa pemrograman, evolusinya ditandai oleh tonggak standardisasi berikut:
- 2001: Spesifikasi awal dipublikasikan di json.org.
- 2006: RFC 4627 diterbitkan oleh IETF sebagai spesifikasi "informational" untuk media type `application/json`.
- 2013: ECMA International menerbitkan ECMA-404, standar formal pertama yang mendefinisikan sintaks JSON.
- 2014: IETF menerbitkan RFC 7159, yang memperbarui RFC 4627 dan memperjelas beberapa aturan.
- 2017: IETF menerbitkan RFC 8259, yang hingga kini menjadi standar Internet (STD 90) yang berlaku. Pada tahun yang sama, JSON juga distandarisasi secara internasional sebagai ISO/IEC 21778:2017.

Saat ini, tidak ada "JSON versi 2.0" atau "JSON 2026". Spesifikasi JSON sangat stabil dan tidak memerlukan pembaruan tahunan karena sintaksnya sengaja dibuat minimalis. Standar yang berlaku adalah RFC 8259 dan ECMA-404.

4. SINTAKS DAN CONTOH BAHASA
JSON dibangun dari dua struktur universal: objek (kumpulan pasangan nama-nilai yang tidak berurutan) dan array (daftar nilai yang berurutan). Nilai dalam JSON dapat berupa string, angka, boolean (`true`/`false`), `null`, objek, atau array.

a. Objek (Object)
Objek dibungkus dengan kurung kurawal `{}`. Setiap pasangan terdiri dari nama (key) berupa string yang wajib diapit tanda kutip ganda, diikuti titik dua `:`, lalu nilai, dan antar pasangan dipisahkan koma.
```json
{
  "nama": "Azriel",
  "umur": 25,
  "aktif": true
}
```

b. Array
Array dibungkus dengan kurung siku []. Nilainya dipisahkan koma dan dapat berupa tipe apa pun, termasuk objek dan array lain.

```json
["apel", "jeruk", "mangga"]
```

c. Nilai Bersarang (Nested)
JSON dapat menyimpan struktur yang kompleks dan bertingkat.

```json
{
  "judul": "Contoh JSON",
  "penulis": {
    "nama": "Azriel",
    "email": "azriel@example.com"
  },
  "tag": ["json", "data", "web"],
  "rating": 4.5,
  "diterbitkan": false,
  "komentar": null
}
```

Aturan ketat yang perlu diperhatikan: kunci harus berupa string dengan tanda kutip ganda, tidak boleh ada koma di akhir (trailing comma), dan komentar (seperti // atau /* */) tidak diizinkan dalam JSON murni.

5. KEGUNAAN JSON
   JSON memiliki kegunaan yang sangat luas dalam dunia komputasi modern:

· Pertukaran Data Web (Web API): JSON adalah format dominan untuk RESTful API. Klien (browser, aplikasi mobile) mengirim permintaan dalam format JSON, dan server membalas dengan JSON.
· Penyimpanan Data Ringan: JSON digunakan sebagai format penyimpanan untuk basis data NoSQL (seperti MongoDB), file konfigurasi (seperti package.json di Node.js), dan file manifest.
· Pertukaran Data Antar-Layanan: Dalam arsitektur microservices, layanan-layanan berkomunikasi satu sama lain menggunakan JSON karena ringan dan mudah diurai.
· Konfigurasi Aplikasi: Banyak alat dan framework menggunakan JSON untuk file konfigurasi karena sintaksnya yang jelas dan dapat dibaca manusia.
· Logging dan Analitik: JSON sering digunakan untuk mencatat log terstruktur yang dapat dengan mudah diurai dan dianalisis oleh sistem monitoring.

6. KELEBIHAN DAN KEKURANGAN JSON

Kelebihan JSON:

· Ringan dan Efisien: Sintaksnya jauh lebih ringkas dibandingkan XML, sehingga ukuran file lebih kecil dan transmisi data lebih cepat.
· Mudah Dibaca Manusia: Formatnya bersih dan intuitif, terutama bagi yang terbiasa dengan bahasa pemrograman C-family.
· Independen Bahasa: JSON dapat digunakan di hampir semua bahasa pemrograman modern tanpa ketergantungan pada platform tertentu.
· Dukungan Luas: Hampir semua bahasa dan framework memiliki pustaka bawaan untuk JSON, menjadikannya standar de facto pertukaran data.
· Hirarki Alami: JSON secara alami mendukung struktur bersarang (nested), yang cocok untuk merepresentasikan data dunia nyata yang kompleks.

Kekurangan JSON:

· Tanpa Skema Bawaan: JSON tidak memiliki sistem tipe atau skema bawaan, sehingga validasi data harus dilakukan secara manual atau dengan alat tambahan seperti JSON Schema.
· Tidak Mendukung Komentar: JSON murni tidak mengizinkan komentar, yang terkadang menyulitkan untuk file konfigurasi yang membutuhkan anotasi.
· Tidak Ada Tipe Tanggal: JSON tidak memiliki tipe data khusus untuk tanggal dan waktu; tanggal biasanya direpresentasikan sebagai string (misalnya format ISO 8601) dan harus diurai secara manual.
· Rentan terhadap Kesalahan Sintaks: Koma berlebih, tanda kutip tunggal, atau kunci tanpa tanda kutip adalah kesalahan umum yang membuat JSON tidak valid.
· Ukuran untuk Data Besar: Untuk kumpulan data yang sangat besar, format biner seperti Protocol Buffers atau MessagePack mungkin lebih efisien daripada JSON berbasis teks.

7. PERBEDAAN JSON DENGAN JSONL (JSON Lines)
   JSON dan JSONL (JSON Lines, juga dikenal sebagai NDJSON atau Newline Delimited JSON) adalah dua format yang berbeda, meskipun JSONL menggunakan JSON sebagai blok bangunannya.

Perbedaan fundamental:

· JSON adalah satu dokumen yang valid. Sebuah file JSON berisi satu nilai JSON (biasanya objek atau array) yang dibungkus dalam satu struktur. File JSON secara keseluruhan dapat diurai (parse) sebagai satu kesatuan.
· JSONL adalah kumpulan baris, di mana setiap baris adalah nilai JSON yang valid dan lengkap. File JSONL secara keseluruhan BUKANlah dokumen JSON yang valid. Setiap baris berdiri sendiri dan dipisahkan oleh karakter newline (\n).

Perbedaan struktural:

· JSON menggunakan array untuk membungkus banyak record: [ {...}, {...}, {...} ] dengan koma di antara elemen.
· JSONL tidak menggunakan array luar dan tidak menggunakan koma di antara baris. Setiap baris adalah objek JSON mandiri: {...}\n{...}\n{...}.

Perbedaan tujuan penggunaan:

· JSON lebih cocok untuk pertukaran data di mana seluruh dokumen perlu dibaca sekaligus (misalnya respons API).
· JSONL dirancang untuk streaming dan pemrosesan record satu per satu. Format ini sangat ideal untuk file log, dataset besar yang tidak muat di memori, dan skenario di mana data ditambahkan secara bertahap (append-only). Karena setiap baris independen, JSONL dapat diproses dengan alat Unix standar seperti grep, awk, dan sed.

Spesifikasi JSONL (jsonlines.org) menetapkan tiga aturan: encoding harus UTF-8, setiap baris harus berupa nilai JSON yang valid, dan terminator baris adalah \n (dengan \r\n juga didukung). Ekstensi file yang disarankan adalah .jsonl (atau .ndjson untuk historical).

8. KESIMPULAN
   JSON adalah format pertukaran data berbasis teks yang ringan, independen bahasa, dan mudah dibaca manusia. Diciptakan oleh Douglas Crockford pada 2001 dan distandarisasi secara internasional melalui ECMA-404, RFC 8259, dan ISO/IEC 21778:2017, JSON telah menjadi bahasa franca bagi aplikasi web modern. Keunggulannya terletak pada kesederhanaan, dukungan universal, dan kemampuannya merepresentasikan struktur data yang kompleks secara alami. Meskipun memiliki keterbatasan seperti tidak adanya skema bawaan dan dukungan komentar, JSON tetap menjadi pilihan utama untuk API, konfigurasi, dan pertukaran data. Varian JSONL memperluas kegunaannya untuk skenario streaming dan pemrosesan data besar, menjadikan ekosistem JSON semakin relevan di era data modern.
