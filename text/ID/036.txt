DAFTAR FITUR WAJIB (SEMUA HARUS DIKERJAKAN)

1. Custom Provider (High)
   - Buat fitur Custom Provider agar pengguna dapat menambah lebih dari 1 Custom Provider.
   - Saat pengguna berganti ke provider yang sudah pernah ditambahkan, pengguna tidak perlu mengisi ulang baseUrl atau API KEY.
   - Nama Custom Provider tidak boleh sama. Harus ada validasi uniqueness.
   - Semua Custom Provider yang ditambahkan harus disimpan secara permanen, bukan hanya untuk sesi berjalan.
   - Pastikan data provider yang disimpan mencakup minimal: nama provider, baseUrl, API KEY, model default jika ada, dan metadata konfigurasi lain yang relevan.
   - Jika provider aktif diganti, sistem harus memuat konfigurasi provider tersebut dari penyimpanan permanen.

2. UI/UX (High)
   - Ubah tampilan output agar yang ditampilkan adalah langkah-langkah yang sedang dilakukan AI, bukan kode mentah yang sedang dikerjakan AI.
   - Output harus berbentuk step by step yang mudah dipahami, misalnya: membaca file, menganalisis struktur, merencanakan perubahan, mengedit file, menjalankan test, melaporkan hasil.
   - Jika ada perubahan file, tampilkan ringkasan perubahan, path file, dan statusnya, bukan memuntahkan seluruh isi kode secara default.
   - Jika pengguna ingin melihat detail kode atau diff, sediakan mekanisme yang jelas dan eksplisit, tetapi output utama tetap berupa langkah-langkah AI.

3. Confirm (High)
   - Buat fitur baru pada command /permissions.
   - Fitur ini mengatur tindakan berbahaya yang dilakukan AI, seperti rm -rf, git push, git push --force, menghapus file, menimpa file penting, atau command berisiko tinggi lainnya.
   - Harus tersedia pilihan:
     - Always Allow
     - Always Ask
     - Always Deny
   - Permission yang dipilih pengguna harus tersimpan permanen.
   - Jangan pernah menjalankan command berbahaya tanpa konfirmasi yang sesuai dengan aturan permission.
   - Jika sebuah command berisiko tinggi tetapi belum ada aturan permission-nya, default harus Always Ask atau minta konfirmasi eksplisit.

4. Lihat folder dan file (Medium)
   - Saat aplikasi dijalankan, AI harus diberi tahu struktur folder di dalam folder user saat itu.
   - Sistem harus menampilkan atau mengirim ringkasan struktur folder working directory ke konteks AI.
   - AI harus dapat meminta aksi: baca file, edit file, tulis file, buat file, hapus file jika diizinkan, list directory, dan operasi filesystem lain yang relevan.
   - Jangan membaca, mengubah, atau menghapus file tanpa mekanisme izin yang benar.
   - Jika struktur folder terlalu besar, buat ringkasan yang aman, misalnya kedalaman terbatas, dengan opsi memperluas jika diperlukan.

5. Jalankan test secara lokal
   - Jalankan test secara lokal untuk memastikan semua fitur berfungsi sesuai requirement.
   - Jika test belum ada, buat test yang proporsional untuk fitur penting: custom provider, persistence konfigurasi, permissions, ESC cancel, system prompt vs custom instructions, dan output UI step by step.
   - Jika test tidak dapat dijalankan karena lingkungan tidak mendukung, tulis status NOT_RUN atau BLOCKED, sebutkan alasannya, dan berikan command test yang seharusnya dijalankan.
   - Jangan menyebut semua berfungsi jika belum ada bukti test atau verifikasi.

6. Update file versi
   - Update version.json agar menjadi versi 1.4.0.
   - Update version-info.json agar konsisten dengan versi 1.4.0.
   - Jika format file sudah ada, ikuti format yang ada tanpa mengubah schema secara sembarangan.
   - Jika file belum ada, buat file yang sesuai dengan struktur proyek yang ditemukan, atau jelaskan jika struktur proyek tidak diketahui.

7. Update CHANGELOG, README.md, dan file terkait lainnya
   - Update CHANGELOG dengan semua perubahan versi 1.4.0.
   - Update README.md agar menjelaskan fitur baru, perubahan perilaku, dan cara penggunaan fitur penting.
   - Update file dokumentasi lain yang relevan jika ada, misalnya docs, configuration guide, permissions guide, atau installation notes.
   - Dokumentasi harus akurat, tidak melebih-lebihkan, dan sesuai implementasi nyata.

8. ESC
   - Tambahkan fitur tekan ESC untuk membatalkan AI yang sedang berjalan.
   - Pembatalan harus menghentikan proses aktif secara aman.
   - Pastikan pembatalan tidak menyebabkan corrupt pada file, config, atau state penting.
   - Jika proses sedang menjalankan command berbahaya atau operasi filesystem, hentikan dengan mekanisme yang aman dan laporkan statusnya.
   - Jika pembatalan penuh tidak mungkin secara teknis, jelaskan batasan dan implementasikan graceful stop sebaik mungkin.

9. Persistence konfigurasi pengguna
   - Pastikan semua konfigurasi yang diatur pengguna tersimpan permanen.
   - Konfigurasi ini mencakup, tetapi tidak terbatas pada:
     - provider aktif
     - daftar custom provider
     - baseUrl
     - API KEY
     - model
     - max token
     - permissions
     - custom instructions
     - pengaturan tampilan atau preferensi pengguna lain yang relevan
   - Konfigurasi tidak boleh hanya bertahan untuk 1 sesi.
   - Gunakan lokasi konfigurasi yang konsisten dan dapat ditemukan oleh pengguna.
   - Jangan menyimpan API KEY di tempat yang mudah bocor, jangan commit secrets, dan jangan menampilkan API KEY secara jelas di log atau output.

10. install.sh
   - Buat atau update install.sh agar setelah instalasi selesai dan sukses, install.sh menghapus dirinya sendiri jika tugasnya sudah selesai.
   - Penghapusan hanya boleh terjadi setelah instalasi benar-benar sukses.
   - Jika instalasi gagal, install.sh tidak boleh menghapus dirinya sendiri, agar pengguna dapat memeriksa atau menjalankan ulang.
   - Tambahkan log yang jelas sebelum dan sesudah instalasi.
   - Pastikan script aman, idempotent jika memungkinkan, dan tidak melakukan operasi merusak di luar proses instalasi.

11. Bedakan System Prompt dan Custom Instructions
   - System Prompt tidak bisa diubah oleh pengguna.
   - System Prompt ditentukan oleh sistem/pengembang, misalnya berisi aturan anti halusinasi, keamanan, larangan mengarang, dan aturan perilaku inti.
   - Custom Instructions adalah instruksi tambahan yang dibuat oleh pengguna.
   - Custom Instructions dapat diatur melalui command /instructions.
   - Custom Instructions tidak boleh menimpa, melemahkan, atau membatalkan aturan inti dari System Prompt.
   - Jika ada konflik antara Custom Instructions dan System Prompt, System Prompt harus menang.
